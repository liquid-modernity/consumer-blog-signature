# Publication CMS

EmDash 1.3.1, Astro 7.3.3, React 19.2.4, Node adapter 11.1.5.
This is the blog's CMS application. The static publication and its UI stay in the
parent application. Engine, Corps and Arsenal packages are unchanged.

From the repository root, use Node 22.22.2+ on the Node 22 line:

```sh
npm run cms:install
npm run cms:dev
```

Admin: http://localhost:4321/_emdash/admin. Bindings are loopback-only.
The existing Catalina esbuild cache and explicit wasm32 compiler dependencies
support this laptop; `.compat/cms-node` holds the checksum-verified local Node.
Other supported hosts use the normal native install. Do not edit package binaries.

SQLite: `cms/.data/cms.db` (WAL). Uploads: `cms/.data/uploads`. Database, sessions,
uploads and secrets are ignored; do not put them in Git or evidence archives.

The one-time migration uses `migration/seed.json`, generated from the eight
admitted editorial records and verified original body hashes:

```sh
node tools/cms/migration.mjs
npm run cms:seed
```

Use `cms:seed` only for an uninitialized local database. Conflicts fail; it never
silently updates existing editorial records. EmDash owns later edits. The source
map preserves application IDs and source paths separately from provider IDs.
Seven articles and one author are separate CMS collections. Original dates,
taxonomy, author references and metadata remain in the structured metadata field;
Markdown is a normal text field. No conversion to a different document language.

Complete the browser setup wizard with your site title, email, optional name and
passkey. No administrator or development-bypass account is generated by this task.
For the local migration proof, create a temporary PAT under
`/_emdash/admin/settings/api-tokens` with `content:read` and `content:write`.
Copy `.env.cms.example` to `.env.cms.local`, set `CMS_LOCAL_TOKEN`, and keep the file
private (mode 0600). Never paste tokens or passkeys into chat.

```sh
npm run cms:verify
```

This command is restricted to localhost:4321. It reads actual EmDash REST items,
checks the imported body and metadata, restores original native publication dates
where present, tests a temporary disposable draft, rejects denied/unauthorized
reads, composes through public Arsenal, and executes public Engine Search. Its
admitted export in `content/emdash/published.json` contains published data and
native provenance, never a token. The separate `cms/migration/local-proof.json`
records the successful real local provider proof. The blog now reads this export.
The original source Markdown is immutable migration evidence.

For later editorial refreshes use the read-only command:

```sh
npm run cms:refresh
```

It requires `CMS_ORIGIN` and `CMS_READ_TOKEN` in the private `.env.cms.local` file
or process environment. Create a separate `content:read` PAT for this purpose;
`CMS_LOCAL_TOKEN` is only the temporary local migration/test credential. Refresh
performs GETs only, rejects unpublished/draft/changed records, and updates the
admitted export and receipt. Review their diff, verify and rebuild. A refresh
cannot itself prove the comprehensive migration test again; the provisioning
proof remains pinned to its originally tested export.

[Production architecture and operator checklist](../docs/EMDASH-ACTIVATION.md).
The dedicated CMS has separately authorized provision/deploy operations in the
EmDash workflow. Store IDs are pinned in provisioning.json and wrangler.jsonc.
No main promotion, publication website deployment or production PAT creation is included.
