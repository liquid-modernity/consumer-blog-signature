# GAGA Policy-as-Code

GAGA treats performance, accessibility, security, and privacy as architecture contracts instead of optional release checklists.

## Layers

1. Source policy: enforced during `validate:signature`.
2. Generated artifact policy: budget schema exists, but hard generated byte thresholds are intentionally deferred until a stable production baseline is measured.
3. Browser evidence: Lighthouse, keyboard, screen-reader, zoom/reflow, and Core Web Vitals require actual browser measurement.
4. Deployment evidence: CSP, Permissions-Policy, HSTS, Referrer-Policy, and X-Content-Type-Options must be verified against the live edge response.

## Transitional debt

The repository currently contains direct browser-storage access and string-based DOM construction. GAGA 0.0.38.3 does not pretend those patterns have already been eliminated. Instead, the exact existing owner files are allowlisted and the validator rejects expansion into new files. Future iterations should centralize storage and replace string-HTML construction so the lists monotonically shrink.

## Origin

The governance pattern is extracted from the Rempah Ruah quality architecture and generalized for Consumer Blog Signature. Rempah Ruah buyer, product, sourcing, and trade semantics are not imported.
